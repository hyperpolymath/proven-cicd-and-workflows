= Zig native FFI gate — tool-dependent pilot
:status: Candidate; not yet published as a reusable GitHub workflow

== Contract

`scripts/zig-native-ffi-gate.sh` orchestrates a real Zig project and the independently authored C ABI consumer harness in `proven-tests-and-benches`. The only successful path is:

. Verify subject Git commit and the *exact* independently checked-out Proven source commit.
. Require the caller's explicit Zig version and verify the installed compiler reports it.
. Build the native library (ReleaseSafe), execute Zig unit/integration tests, and check source formatting.
. Require the resulting static archive; compile/link/execute the C consumer using the Proven runner.

Required environment: `ZIG_PROJECT_DIR`, `ZIG_VERSION`, `PROVEN_TESTS_ROOT`, `PROVEN_TESTS_SHA`, `C_ABI_HEADER`, `C_ABI_CONSUMER`, `C_ABI_ARCHIVE`. All paths are repository-relative. `CC=zig cc` is appropriate for Zig-built libraries; supply a compiler whose linkage is independently qualified. Callers must install the specified compiler and fetch the external tests repository at a reviewed full 40-hex commit *before* running this script. The gate does not download toolchains or select floating source refs.

=== Outcome discipline

* 0 means the specified build, tests, formatting and C consumer **actually executed** and passed on the identified revision.
* 1 means a substantive build/test/format/contract check failed.
* 2 means an unavailable tool, missing source, bad pin, mismatched compiler or absent output: **NOT RUN**.

Both 1 and 2 must fail the consumer's required GitHub check. The script never marks a skipped check as success, never launches arbitrary shell from YAML inputs, and never claims a successful C test as an Idris2 proof. `tests/zig-native-ffi-gate.sh` uses stand-in Zig and contract commands to plant failing and missing stages; these fixtures qualify **orchestration**, not compiler behavior. Qualification of the real subject must be supplied by a live consumer such as Checky Monkey.

== Migration discipline

This is an additive **pilot** under the established `Language Gates Self-Test` context; it is not a new required check, an action, or a replacement for governance/security workflows. In a consumer, introduce it **inside the existing stable required native test job**, prove that job runs on actual PRs and main, and only remove duplicated local commands after the end-to-end canary passes. Do not change the required status-context string and remove the old job in the same step. No administrator override is part of the migration. Missing results are an escalation, never a waiver.

The full 18-category testing taxonomy and 14 cross-cutting aspects remain governed by metadatastician/standards. The Proven-Tests evidence/reporting schema presently retains its separately versioned 17-category boundary; this execution gate does not invent category-18 proof receipts.
