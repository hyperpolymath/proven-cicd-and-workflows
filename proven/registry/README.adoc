= Hypatia to squabbler rule map

`sq-map.tsv` is the one map between Hypatia rule ids (A5 form
`hypatia/<module>/<name>`, the stable key) and squabbler rule ids
(`SQ-<FAMILY>-NN`). It was agreed with the squabbler owner on 2026-11-13. The
squabbler's own table carries no A5 column, because the squabbler does not
depend on Hypatia and the mapping is many to one. Dispatch, meaning class,
recipe and sequencing, stays with the squabbler and Hypatia (R1, ADR 0004).

== Columns

Tab-separated: `a5_id`, `sq_id`, `status`, `praxis`, `note`.

[cols="1,4"]
|===
| `status` | `mapped`: the A5 id maps to exactly one SQ id. `hypatia-only`: no squabbler rule. `unmapped`: a triage id in Hypatia's registry that ADR 0004 does not map yet (`sq_id` is `unassigned`); which SQ rule it gets is the squabbler owner's decision. `squabbler-only`: an SQ id with no A5 id (`a5_id` is `-`). `kernel-reason`: a lock-kernel reason (named in `note`) and the SQ rule it serves (`a5_id` is `-`).
| `praxis` | `present` or `absent`: whether the A5 id is in Hypatia's `hypatia_rules_praxis.deed`. `-` for rows with no A5 id.
|===

== Rules the conformance test enforces

`tests/registry-sq-map.sh` enforces these rules, and both the squabbler and
Hypatia can run it:

* Every A5 id appears once and maps to exactly one SQ id, or to `hypatia-only`, or is listed `unmapped` (printed as a warning).
* An SQ id may appear on several rows.
* Every SQ id in the squabbler table is in the map, and the map names no SQ id the table lacks (given `SQUABBLER_RULES`).
* The `praxis` column matches the registry, and every `hypatia/ci_failure_triage` id in the registry has a row (given `HYPATIA_PRAXIS`). Without the second half a rule Hypatia adds would stay out of the map and the test would still pass.
* A *pending* row is `unmapped` with praxis `absent`: a triage rule on its way. While the registry lacks its id it is a warning. Once the registry holds the id, `HYPATIA_PRAXIS_AT` decides: `head` (the weekly or dispatched run against Hypatia main) warns to flip the column to `present`; `pin` (the default, every push and pull request) fails, because the pin has moved past the rule. Any other value is NOT RUN. Every other row keeps strict equality with the registry at the pin.
* With `HYPATIA_PRAXIS_SOURCE=1` (Hypatia's own CI, `scripts/check-sq-map.sh`, which passes a change's registry rather than a pinned one) a praxis mismatch is a warning, because the column describes the registry at this repository's pin. A missing row still fails.
* Every `kernel-reason` row names a reason the lock kernel emits (given the kernel source).

The rules allow `squabbler-only` and `hypatia-only` rows, so the test can pass
on day one: 21 of the 45 squabbler rules have no log matcher, and many owner
rules have no Hypatia id.

== Adding or removing a Hypatia triage rule

Neither repository merges red if the steps run in this order (the flow is a control in `tests/registry-sq-map-controls.sh`):

. Add the row here first, pending: `<id>\tunassigned\tunmapped\tabsent\t<note>`. It passes against the pinned registry, which lacks the id.
. Re-run Hypatia's SQ map source check on the change that adds the rule. It reads this repository at `main`, finds the row and passes.
. After the Hypatia change merges, the weekly run against Hypatia main (`HYPATIA_PRAXIS_AT=head`) warns that the pending row is in the registry now. Flip its column to `present` in the change that moves the Hypatia pin past it. That change fails until the flip is in it: at the pin (`HYPATIA_PRAXIS_AT=pin`, the default) a pending row whose id the pinned registry holds is a FAIL, "the pin has moved past <id>". A flip before the pin moves fails too.

A rule Hypatia removes: Hypatia's check warns about the column and passes. The change here that moves the pin past the removal must set that row's column to `absent` (or drop an `unmapped` row), or it fails.

A row added `present` before the Hypatia change merges fails here against the pin; that is why a new row starts pending.

== Sources and open findings

* `cicd-squabbler` at `09e6790` (`09e6790d188444abb2a96adba758984fb3cf13e0`): `crates/squabble-core/data/first-line-rules.tsv`, which holds 45 SQ ids, and ADR 0004, section "Mapping to Hypatia's `ci_failure_triage` ids". CI reads the table the same way as Hypatia's registry: a sparse checkout at this pinned commit on a push or pull request (`SQUABBLER_RULES`), and the squabbler's default branch on the weekly schedule and a manual dispatch. Move the pin when the table changes.
* `hypatia` at `f955ace` (`f955ace8d0056e21dd92f797c7f26c2ddf864d2c`): `hypatia_rules_praxis.deed`, which the test reads as 432 praxis ids. On a push or pull request CI checks it out at this pinned commit (git verifies the content); move the pin whenever the registry changes. A weekly scheduled run (and a manual dispatch) checks against Hypatia's default branch instead, so drift after the pin shows within a week.
* ADR 0004 names the triage ids without a module. They are written here as `hypatia/ci_failure_triage/<name>`, after `lib/rules/ci_failure_triage.ex`.
* *Resolved finding:* the 26 A5 ids were once absent from the praxis registry, because the generator was not re-run after hypatia#1064. hypatia#1075 regenerated it, and all 26 are now `present`. Two of them, `actions_lock_stale` and `mirror_without_visibility_guard`, are emitted by `workflow_audit` rather than `ci_failure_triage`, so their A5 ids use that module.
* `api_rate_limit` maps to SQ-RUN-01, the generic rate-limit rerun, as the squabbler owner ruled on 2026-11-13. SQ-PIN-03, the setup-bun root-cause fix, takes precedence when the failed step is setup-bun. The note records that precedence, and SQ-PIN-03 is `squabbler-only`.
* *Open finding (2026-11-14):* the squabbler's default branch has three SQ ids that `09e6790` lacks: `SQ-GEN-05`, `SQ-RUN-05` and `SQ-RUN-06`. The map has no row for them, so the weekly run against the default branch fails until they are classified (mapped, or `squabbler-only`), which is the squabbler owner's decision; then move the pin.
* `generated_file_stale`: ADR 0004 gives no squabbler rule, only a referral, so the row is `hypatia-only`.
* The kernel reason `Illegal` (`../`, job-level `$/`) has no squabbler rule, on purpose: it is a referral. The squabbler owner declined to put an unproven repair at the first line while the `$/` measurement is disputed. The row says `unassigned`, which is allowed only for kernel-reason rows and printed as a warning, until the owner rules.

* 22 triage ids in the registry had no row: ADR 0004 does not map them. They are listed `unmapped` until the squabbler owner rules: `actions_lock_tag_keyed`, `codeql_no_source`, `codeql_setup_conflict`, `compile_error`, `dependency_advisory`, `format_diff`, `github_state_unreadable`, `hypatia_pin_drift`, `process_segfault`, `required_check_never_reported`, `review_quota_exhausted`, `review_rate_limited`, `rollup_cascade`, `runtime_exception`, `security_findings_reported`, `shellcheck_findings`, `ssh_key_secret_empty`, `test_failure`, `toolchain_segfault`, `unrecognized_failure`, `upstream_artifact_missing`, `workflow_startup_failure`.

Row counts: 25 `mapped`, 1 `hypatia-only`, 22 `unmapped`, 23 `squabbler-only` and 17
`kernel-reason`, 88 in all. `hypatia_pin_drift` and `shellcheck_findings` were added at the `f955ace` pin.
